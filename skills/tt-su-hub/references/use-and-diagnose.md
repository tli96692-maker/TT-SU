# 安装、诊断和检查更新

## 安装与打开

1. 确认用户实际使用的 SketchUp 年份、系统和 TT中枢版本。`0.2.3-beta.1` 仅声明 Windows / SketchUp 2024 兼容。
2. 发行来源从用户提供的真实仓库、已安装包的 `release.json` 或仓库 Git remote 核实。GitHub Release 附件 `su_zhongshu-core.rbz` 才是安装包；GitHub 自动生成的 Source code ZIP 是源码。
3. 对照该 Release 的 `SHA256SUMS.txt` 计算本机 RBZ 的 SHA-256。只比较发布者给出的可信对应版本，不把校验和称作签名。签名状态以 SketchUp 扩展管理器识别结果为准；签名阻止加载时检查包来源或让维护者补签名，不引导关闭安全加载策略。
4. 保存模型；升级时保留原有 `su_zhongshu.rb`、`su_zhongshu` 目录和设置备份。通过 SketchUp“扩展程序管理器 → 安装扩展程序”选择 RBZ，完成后重启；若用文件方式替换，先确认 SketchUp 已退出。
5. 从“扩展程序 → SU 中枢 · 面板”打开。验证插件版本、内置工具列表、诊断状态和“关于与更新”。普通使用者无需安装 Ruby、Node.js、Python、Git 或 Codex。

设置通常位于 `%APPDATA%/SUZhongShu/settings.json`；若当前进程指定 `SUHUB_SETTINGS_DIR`，以实际目录为准。不要从读取失败推断可以删除设置；先检查只读诊断和 `settings.last-good.json`、backups 中已有副本。

## 按症状排查

| 现象 | 优先核对 |
|---|---|
| 菜单没有出现 | 扩展是否启用、是否选错 SU 年份、签名/加载错误、是否重启 |
| 只有 7 个内置工具 | 符合公开 Core 范围；额外第三方插件并不随 Core 分发 |
| 第三方官网入口无法执行命令 | 是否实际安装作者插件及其依赖；入口只是下载/信息链接 |
| 设置不能保存 | 诊断中的目录、权限、只读原因和设置 schema；保留异常文件及恢复副本 |
| 无法找到更新 | 关于与更新中的 repository、channel、当前版本、网络错误及对应 Release 附件 |
| 几何操作失败 | 用模型副本记录选择类型、尺寸、工具参数、最小复现和错误；避免在原模型反复试验 |

导出诊断供他人查看前移除个人用户名、绝对路径和私人模型内容。输出时区分“代码检查”“离线测试”“浏览器界面测试”和“SketchUp 实机验证”。

## 更新结果如何解释

- `unconfigured`：安装包未绑定仓库。创建 GitHub 仓库不会改变已安装包；需要安装一次绑定真实仓库的新包。
- `no_release` / `source_unavailable`：检查仓库是否公开、是否已有公开 Release。草稿匿名不可见；只有提交源码也没有可安装更新。
- `offline` / `rate_limited`：保留原安装，等待网络恢复或限流解除再试。不要通过无限重试绕过限制。
- `incompatible` / `compatibility_unknown`：查看发行版兼容范围，不强制安装。
- `available`：显示目标版本、兼容性和真实 Release 链接；下载、校验、安装并重启后复核版本。

面板连接宿主后自动后台检查一次，也支持手动检查。同一 SketchUp 进程成功结果缓存 10 分钟，失败结果缓存 30 秒；短时间反复点击可能看到缓存。`preview` 可看预发行；`stable` 排除预发行。现有实现不自动替换安装文件、不自动回滚。

回退先遵循相应版本的迁移说明，保存模型并退出 SketchUp，再恢复 TT中枢备份或安装上一版已签名 RBZ。未来新版设置不一定能由旧版读取，不能只降代码而忽略设置版本。
